# Screens batch 3 (Phase 4) — design

Date: 2026-11-20 · Status: approved by standing instruction ("sigue hasta el final desde ahora sin parar") — all calls are ours.

Same machinery and rules as Phases 2–3 (specs `2026-11-20-bake-screens-design.md`, `2026-11-20-screens-batch-2-design.md`; README "Screens (bake)"): sample data in the controller, translatable strings (`t`), `#` + TODO for non-generated actions, GET forms to `index`, POST only via postButton when a URL is wired, invented Fernway data, no third-party template references, CSP-safe (no inline JS/styles), Lucide icon rules (sr-only names, one icon per meaning, `ellipsis` = menus), Avatar `decorative` next to visible names, no horizontal page scroll at 390px, light/dark.

## Screens (own composition; builders must NOT open docs/roadmap)
- **bookings** (`Bookings`): resource day schedule for a fitness studio ("Fernway Fit" is NOT used — the studio is an invented CrossFit-style box, e.g. "Ironbark Box"): header with date navigation (previous/next day as GET `?date=`, current date label), grid/list view switch, "New booking" action. Grid: time rows (06:00–21:00, hourly) × resource columns (rooms/coaches: e.g. "Main floor", "Rig", "Open gym", "Coach Ana"), class blocks positioned by start/end (CSS grid rows, no inline styles: use row-span utility classes generated from data, or one row per hour slot), each block with class name (WOD, Weightlifting, Mobility, Open gym…), coach, time range, capacity "12/16", colour by class type + text type label, `ellipsis` menu. List view: table of the same bookings. Grid scrolls horizontally inside its own container on phones (relative container).
- **calendar** (`Calendar`): month view with prev/next/today (GET `?month=`), month/week/day switch (only month rendered; others TODO), a 7-column grid of days (leading/trailing days muted, today marked with text sr-only "Today"), events as chips (time + title, colour + text category), "+N more" overflow; side panel on desktop with upcoming events list and a mini legend of categories. Proper `<table>` or grid with `role="grid"` semantics and day headings.
- **profile** (`Profile`): user profile page: cover band (CSS gradient), avatar, name, role, location, "Edit profile" + "Message" actions; tabs (Overview / Activity / Projects / Settings via Tabs helper); Overview: about card, details list (email, phone, timezone, joined), skills badges, stats MetricCards; Activity: timeline list; Projects: cards grid with progress; Settings: form (name, email, bio textarea, notifications switches) posting to `#` TODO.
- **onboarding** (`Onboarding`): multi-step onboarding flow: step indicator (numbered steps with current/completed states as text, `aria-current="step"`), step panels rendered via `?step=` GET (1 Workspace: name + URL slug; 2 Team: invite emails list; 3 Plan: ChoiceCards; 4 Preferences: switches/selects; 5 Done: summary), Back/Continue buttons (GET links/forms between steps; final "Finish" inert TODO). Centered card layout, works without JS.
- **file-manager** (`Files`): storage overview (used/total Progress + per-type breakdown), folders grid (folder cards with file count and size), recent files table (name with type icon, owner avatar decorative + name, size, modified, `ellipsis` menu), upload action (inert TODO), search + type filter (GET), breadcrumb of the current folder (`?path=`), grid/list switch.

New icons needed → Task 0 adds them (e.g. `clock`, `map-pin`, `briefcase`, `upload`, `folder-open`, `file-image`, `file-video`, `file-audio`, `file-archive`, `hard-drive`, `calendar-days`, `dumbbell`, `rocket`, `building-2`, `globe`, `phone` exists?, `user-plus`). Registry entries: bookings (icon `calendar-clock` or `dumbbell`), calendar (`calendar-days`), profile (`circle-user`), onboarding (`rocket`), file-manager (`folder`).

## Work split
Task 0 (one agent): registry entries + icons + tests, commit. Then five parallel screen agents (own files only, no commits). Then two reviewers (with browser checks at 390/1280, light/dark), one fix wave, re-review, merge.
