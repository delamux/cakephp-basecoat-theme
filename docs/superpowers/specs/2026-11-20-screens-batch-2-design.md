# Screens batch 2 (Phase 3) — design

Date: 2026-11-20 · Status: approved by standing instruction ("sigue hasta el final desde ahora sin parar") — all calls below are ours.

## Intent
Add six more `bake screen` screens using the Phase 2 machinery (ScreenRegistry + `templates/bake/Screen/<slug>/{template.twig,data.php}` + catalog Screens section): **chats**, **ai-chat**, **mail**, **todo**, **kanban**, **notes**. Same rules as Phase 2 (spec `2026-11-20-bake-screens-design.md`): sample data in the controller, translatable strings like the CRUD bake templates, `#` + TODO for non-generated actions, GET forms to `index`, POST (`Form->postButton`) for state changes when a URL is wired, invented Fernway data, no third-party template references, CSP-safe, Lucide icon accessibility rules, catalog renders exactly what bake writes.

## Screens (own composition; screenshots in docs/roadmap are inspiration only and are NOT to be opened by builders)
- **chats** (`Chats`): two-pane messenger. Left: title + "New chat" icon button, search, conversation list (avatar with online status dot + sr-only status, name, last message preview, relative time, unread count badge; group chats with a users icon); selected row highlighted. Right: header (avatar, name, online status, call/video/more icon buttons named via sr-only), message thread reusing the `Conversation` helper (sent/received bubbles, time, read receipts as text/sr-only), composer with attach/emoji/voice icon buttons and Send. Responsive: list collapses above thread on small screens.
- **ai-chat** (`Assistant`): assistant chat. Empty-state hero (title + short prompt suggestions as buttons) above a message thread (user messages and assistant answers with simple formatted text / code block), a composer with model select, attach button and Send; no animated orb or decorative motion (explicit user rule: skip the rolling SVG ball).
- **mail** (`Mail`): three-pane mailbox. Left nav: compose button, folders (Inbox with count, Starred, Sent, Drafts, Archive, Spam, Trash) and labels. Middle: search + Unread/All tabs + message list (sender, subject, snippet, time, unread marker, labels). Right: reading pane (subject, from/to, date, actions reply/forward/archive/delete as named icon buttons, body, reply box).
- **todo** (`Tasks`): task list. Header with "Add task", filter tabs (All / Active / Completed), search; grouped list (Today, Upcoming, Later) of tasks with a real checkbox (label = task title), title (struck when done, plus sr-only "completed"), priority badge (text), due date, assignee avatar, tag badges, row menu. Checkboxes in a GET-less form; toggling is a TODO.
- **kanban** (`Board`): board with view switch (Board/List as a tab group; List renders the same tasks as a table), columns (Backlog, In progress, Review, Done) each with count, add-card button; cards with title, description, assignee avatars, progress (Progress helper or text percent), priority badge, due date, attachment/comment counts (icon + number + sr-only label). No drag & drop in this phase (TODO hook `data-kanban-*` documented, no JS required).
- **notes** (`Notes`): notes workspace. Left: "New note" button, nav (Notes with count, Archive, Edit labels) and colour-dot labels (dot + text). Main: search, grid/list toggle, masonry-like responsive grid of note cards: text notes, checklist notes (checkboxes with labels, done items struck + sr-only), notes with an image (local SVG/gradient placeholder, alt text, no external images), label badges.

New helpers only if a block is clearly reusable (candidates: `ChatList` for conversation lists, `KanbanColumn`/`KanbanCard`); if created: full Phase 1 treatment (AbstractComponentHelper, tests incl. escaping/empty/unique ids, catalog examples). Missing Lucide icons are added to IconHelper in Task 0.

## Approach / work split
Task 0 (one agent, first): registry entries for the six screens (title, description, default controller, icon) + any icons they need in IconHelper (`message-circle`, `sparkles`, `list-checks`, `sticky-note`, `star`, `archive`, `paperclip`, `smile`, `mic`, `phone`, `video`, `reply`, `forward`, `tag`, `layout-grid`, `image`, `flag` — Lucide paths, tests). Then six parallel agents, one per screen, owning only `templates/bake/Screen/<slug>/**`, `tests/TestCase/Bake/<Slug>ScreenTest.php` and any new helper of their own (`src/View/Helper/<Name>Helper.php`, its test, `docs/catalog/examples/<slug>/`). Shared files (BasecoatHelpers MAP, docs/catalog/helpers.php, locales, README, webroot JS) → integration requests applied by one final integration agent, then a whole-branch review and one fix wave.
